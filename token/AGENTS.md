# トークン効率使用ハーネス

**原則: モデルに全文を読ませず、決定論的な道具に計算させて結果だけ読む。**
効くレバーは「読む量」「往復の回数」「書く量」の3つ。道具: `bin/token_budget.py`（測定）・`bin/memory.py`（安い検索）。

## 1. 読む量を減らす

| やりたいこと | 安い読み方 | 避ける読み方 |
|---|---|---|
| 過去の知見を探す | `python bin/memory.py search "<語>" --type <種別>`（結果だけ読む） | フォルダの全文読み |
| 一覧・棚卸し | frontmatter だけ抽出（全文の約1/6） | 全ファイルを開く |
| 大きいファイル | 範囲指定で必要な行だけ | 先頭から全部 |
| ファイルが見つからない | 綴り・引用符を確認 → 無ければ報告して終了 | ドライブ全体の再帰検索 |

- 検索は1問につき3回まで。空振りの反復が最も高くつく。
- 裏取りが要るときだけ原文を開く（索引→要約→原文の順）。

## 2. 往復を減らす

- 独立したツール呼び出し（複数ファイル読み・状態確認）は**1回にまとめて並列**で出す。
- 数回の操作で終わる仕事を別エージェントへ委譲しない（委譲先は規約一式を読み直すので倍以上かかる）。
- 自分の作業の検証のためだけに別エージェントを呼ばない。
- 機械で合否が判定できる作業は「全部を低い思考量で → 失敗分だけ既定で再実行」が最安。

## 3. 書く量を減らす

- 結論から書く。前置き・依頼の復唱・末尾の繰り返し要約を書かない。
- 進捗報告は「着手前に1文」と「重要な発見・方針転換の時だけ」。
- ファイルに書く成果物は中身に必要な長さに合わせる（埋め草の節を作らない）。
- 常時読み込まれる指示ファイルに追記しない。追記したくなったら、該当作業時だけ読まれる場所へ置く。

## 4. セッションの運び

- **モデルはセッション冒頭で決め、途中で変えない**（モデル切替はキャッシュ全失効）。思考量（effort）の変更でキャッシュが保たれるかはモデルと接続経路で異なる（公式 prompt-caching 文書で確認する）。
- キャッシュを失効させる操作: モデル切替・fast mode の切替・MCP サーバーの追加・会話の要約圧縮。作業の途中で行わない。
- 長く離れるなら区切る（要約して新しいセッションで再開）。キャッシュの寿命はサブスクリプション枠内の主会話で約1時間、従量課金・APIキーでは約5分（2026-10 時点の公式文書。変わりうる）。
- 思考量はモデル切替より効くレバー。品質が保てる作業は低めにする。**思考量が決めるのは考える量で、出力の長さではない**（長さは §3 で別に抑える）。
- 失敗した道は巻き戻しで捨てる。要約圧縮はタスクの区切りでだけ行う。
- 使わない外部接続（MCP等）は起動しない。
- コンテキスト95%に達したら止め、引き継ぎファイル（プロジェクトごとに1本だけ。新設で散らさない）へ 目的/完了/未完/次の一手/注意 を書いて終える。

## 5. 測る

```
python bin/token_budget.py
```

常時読込の指示量（静的な推定）を台帳（`~/.claude-harness/state/context-budget-log.jsonl`）へ記録し、予算超過・急増・200行超のファイルを警告する。
`@` 取込（4段まで）・上位ディレクトリの CLAUDE.md・`paths:` の無い rules・管理ポリシーも数える。
予算と対象は `harness.config.json`（PC固有は `harness.config.local.json`）。SessionStart フックが毎回 `--quiet` で実行し、警告時だけ注入する。
警告が出たら、直近で常時読込ファイルに足した行を「消したら間違えるか」で見直す。

Claude Code 内での実測:

- `/context` … いま文脈に何が何トークン載っているか（推定ではなく実際の内訳）。
- `/usage` … 利用枠とキャッシュの命中。命中が低いなら「途中でモデルや MCP を変えていないか」を疑う。
- 話題を変えるなら `/clear`（費用ゼロ）。要約を残したいときだけ `/compact`（要約の生成自体に費用がかかる）。失敗した道は `/rewind`。

## やらないこと

- 課金を伴う実行（外部API・従量クレジット・スケジューラ）を独断で行う。**毎回ユーザー承認**。
- 省トークンのために検証・安全確認そのものを省く（省くのは重複した確認だけ）。
